# 아키텍처 결정 기록

ADR(Architecture Decision Record)은 여러 영역에 장기적으로 영향을 주는 기술 결정을 기록한다.

## ADR이 필요한 경우

- 모듈 구조와 의존 방향 변경
- 하나의 앱 모듈과 여러 앱 모듈 사이의 선택
- Product Flavor, Build Type, 배포 단위 결정
- DI, 상태 관리, 네트워크, 저장소 기술 선택
- 버전, 서명, 보안, 릴리스 정책 변경
- 기존 저장소 아키텍처 규칙의 예외 도입

단순 버그 수정, 이름 변경, 포맷 수정, 이미 승인된 규칙의 반복 적용에는 ADR을 만들지 않는다.

## 파일 이름

```text
0001-결정-제목.md
0002-다음-결정-제목.md
```

번호는 저장소 안에서 증가시키고, 파일 이름은 결정의 내용을 짧게 표현한다.

## 상태

- `제안됨`: 논의 중이며 아직 강제하지 않음
- `승인됨`: 현재 적용하는 결정
- `대체됨`: 새로운 ADR이 이 결정을 대체함
- `폐기됨`: 더 이상 적용하지 않음

승인된 결정을 바꿀 때 기존 기록을 조용히 덮어쓰지 않고, 새 ADR에서 대체 관계를 적는다.

## 템플릿

```md
# ADR-0001: 결정 제목

- 상태: 제안됨
- 날짜: YYYY-MM-DD
- 관련 이슈:
- 대체하는 ADR:

## 배경

어떤 문제, 제약, 요구사항 때문에 결정이 필요한가?

## 결정

무엇을 선택했는가?

## 결과

### 장점

- 얻는 효과

### 비용과 위험

- 감수해야 하는 제약

## 검토한 대안

- 대안과 선택하지 않은 이유

## 검증

- 이 결정이 유효함을 어떻게 확인할 것인가?

## 재검토 조건

- 어떤 조건에서 다시 검토할 것인가?
```
