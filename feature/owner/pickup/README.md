# 점주 찜 현황·픽업 처리

[#66](https://github.com/SWYP-APP-S6/frontend/issues/66)의 UI 구현. `origin/develop`의 `a4d5664`에서 분기했다.

## 화면과 진입점

- `OwnerPickupRoute`: 목록의 전체/픽업완료/픽업불가/찜 취소/만료 필터, 상세, 재고 부족 취소 화면과 확인 바텀시트.
- `Pickup`: 한 상품의 수량 단위 찜. 고객, 상품, 단가·수량·총액, 요청 시각, 마감 시각, 처리 상태를 전달한다.
- 화면 내부에서는 선택한 찜 id, 필터, 취소 선택만 저장한다. 목록과 재고는 호출자 소유다.
- `:app`은 `ownerImplementation`으로만 의존한다. Owner 초기 화면의 `찜 현황` 버튼으로 진입하고 상세에서 홈으로 돌아갈 수 있다.
- `ownerDebug`의 샘플 데이터와 로컬 처리로 동작을 확인한다. 홈에 개발용임을 표시한다. 홈 복귀·재진입 시 샘플 상태를 보존한다.
- `ownerRelease`는 빈 상태를 제공한다. 실제 API·메시지 발송·데이터 영속화는 아직 연결하지 않았다.
- 점주 홈(#64) 및 등록 상품 탭(#65)은 이 브랜치에 합치지 않았다. 다른 모듈 연결 시 앱의 임시 진입점을 최상위 내비게이션으로 교체한다.

## 상태와 서버 연동 계약

- 현재 시각이 마감 시각 이상이면 대기 중인 찜만 만료 처리한다. 완료·픽업불가·고객 취소 상태는 만료로 덮어쓰지 않는다.
- 재고는 이미 픽업한 수량을 뺀 실제 재고다. 아직 재고가 조회되지 않은 상품은 자동 취소 대상으로 판단하지 않으며 픽업도 비활성화한다.
- 상품별로 요청 시각 오름차순(id를 동률 기준으로 사용)으로 수량을 배정한다. 누적 요청량이 재고를 초과하는 요청은 전체 취소 대상이다. 부분 취소는 지원하지 않는다. 후순위의 작은 요청이 선순위를 건너뛰지 않는다.
- 선택한 취소 요청만 콜백에 전달한다. 전체 선택 해제 또는 0건이면 실행할 수 없다. 취소 대상이 만료·변경되면 선택과 미리보기 건수도 갱신된다.
- 픽업 완료와 취소 실행 직전에 현재 시각과 배정 결과를 확인한다. 실행 중 추가 실행과 화면 이탈을 막는다. 콜백 실패 시 상태를 완료로 표시하지 않고 재시도할 수 있다.
- `onCompletePickup(id)`: 서버에서 활성 상태·재고·만료를 원자적으로 검증하고 픽업 처리한다. 성공 후 최신 목록과 실제 재고를 함께 전달한다.
- `onCancelPickups(ids, message)`: 서버에서 대상의 최신 상태를 재검증하고 취소 및 안내 발송 요청을 원자적으로 접수한다. 정상 반환 전에 목록을 갱신한다. 서버 측 멱등성 키와 발송 재시도 처리는 데이터 계층 책임이다.
- 클라이언트의 재고 배정은 UI 표시용이다. 서버 시간, 서버 순번과 배정 결과가 최종 기준이어야 한다. 이 브랜치는 외부 안내 메시지를 발송하지 않는다.
