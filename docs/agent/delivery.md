# 변경 전달 규칙

이 문서는 변경을 커밋과 PR로 전달할 때 필요한 정보와 검증 증거를 정의한다.

## 커밋 메시지

일반 변경 형식:

```text
<type>: [<작성자>]: <설명>
```

예시:

```text
docs: [geonwoo.kim]: 에이전트 하네스 문서 추가
test: [geonwoo.kim]: 검증 스크립트 테스트 추가
```

일반 변경에서 허용하는 type:

- `feat`, `fix`, `docs`, `style`, `refactor`, `test`, `chore`

빌드와 릴리스 메시지는 `.githooks/commit-msg`의 별도 버전 형식을 따른다. 검증 정규식의 원본은 해당 hook 파일이다.

## PR 필수 내용

1. 변경 목적
2. 주요 변경과 의도적으로 제외한 범위
3. 영향받는 모듈, 빌드, 화면, 리소스
4. 실행한 검증 명령과 결과
5. 실행하지 못한 검증과 이유
6. UI 변경 시 전후 화면 증거
7. 알려진 위험과 후속 작업

## 에이전트 완료 보고 형식

```text
변경
- 파일: 변경 이유

검증
- 성공 또는 실패: 실행한 명령

미실행
- 검증 항목: 실행하지 못한 이유

남은 위험
- 없음 또는 구체적인 내용
```

## 전달 전 확인

- 관련 없는 파일이 변경되지 않았는지 확인한다.
- 디버그 코드, 임시 로그, 불필요한 TODO가 남지 않았는지 확인한다.
- 동작이나 구조가 바뀌었다면 관련 문서를 갱신한다.
- 실행하지 않은 검증을 체크하거나 성공으로 표시하지 않는다.
- 사용자의 요청 없이 에이전트가 커밋이나 푸시하지 않는다.
